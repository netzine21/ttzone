# 탁구장 게임관리 시스템

탁구장 관장님이나 게임 운영자가 회원을 등록하고, 로그인 후 게임을 생성할 수 있는 MVP입니다.

## 현재 구현

- 회원가입
  - 필수: 닉네임, 아이디, 비밀번호, 성별, 통합부수, 휴대폰번호, 활동지역
- 로그인
- 비로그인 공개 게임목록
  - 생성된 게임만 노출
  - 게임제목 클릭 시 경기요강 기본 표시
  - 대회현황 탭에서 경기형식별 참가선수 현황 조회
  - 회원은 로그인 후 저장된 선수정보로 간편 신청
  - 비회원은 이름·성별·부수(복식·단체전은 팀명 추가)로 신청
  - 비회원 본인 신청은 전용 링크로 조회·수정·취소
  - 단체전은 팀별 참가선수 현황 조회
  - 참가신청 버튼 선택 시 회원·비회원 신청 방식 선택
- 로그인 후 참가신청
  - 로그인 전 선택한 게임 상세로 자동 이동
  - 개인전/복식/단체전 게임별 참가신청
  - 중복신청 방지 및 최대참가인원 마감 처리
  - 참가자 수와 참가자 목록 표시
- 운영자 참가선수 일괄등록
  - 게임 운영자만 명부 업로드 가능
  - 엑셀에서 CSV 또는 TSV로 저장한 명부 업로드
  - `닉네임` 또는 `선수명` 열 인식
  - 선택적인 `아이디` 열로 가입 회원 연결
  - 양식 다운로드, 중복 및 정원 초과 자동 제외
- 게임 생성
  - 필수: 게임명, 게임장소, 경기형식, 게임일시, 최대참가인원
  - 선택: 게임 안내문
  - 경기형식은 개인전·복식·단체전 중 1개 이상 복수 선택 가능
  - 선택한 경기형식별 참가신청 양식 제공
- 게임 수정
  - 게임 운영자 본인이 만든 게임만 수정
  - 게임명, 장소, 경기형식, 일시, 최대참가인원, 안내문 수정
  - 경기형식 여러 개 동시 운영 가능
- 경기형식별 참가신청
  - 개인전: 이름, ID(선택), 부수
  - 복식·단체전: 팀명, 이름, ID(선택), 부수
  - 형식별 참가자와 정원 분리 관리
  - 한 게임에서 여러 경기형식에 각각 신청 가능
  - 게임 상세에서 경기형식별 참가현황 확인
  - 단체전은 팀별 참가자 묶음으로 확인
  - 현재 참가자 수보다 작은 최대참가인원 저장 방지
- 운영자 전용 경기운영
  - 운영자 본인이 생성한 게임만 경기운영 메뉴에서 선택 가능
  - 경기종목별 예선리그 조편성
  - 조 수를 운영자가 지정하면 조별 인원/팀 수는 자동 균등 계산
  - 나머지 인원/팀은 무작위 조에 추가 배정
  - 개인전: 부수 중복을 줄이고 부수별로 골고루 분산
  - 복식·단체전: 참가자 무작위 배정
  - 생성 후 선수별 조 이동 및 조편성 수정 저장
  - 참가선수 일괄등록 메뉴에서 게임·경기종목별 명부 업로드
- 예선리그 대진표
  - 조별 단일리그 자동 대진
  - 개인전은 선수 대 선수, 복식·단체전은 팀 대 팀
  - 11점 5전 3선승 규칙 표시
  - 조별 전용 탁구대와 경기 순번 자동 부여
  - 조별 대진 매트릭스와 전체 경기 순서표 제공
  - 경기별 세트 스코어와 승자 입력 및 저장
- 본선 토너먼트
  - 예선 조별 승수와 세트 득실을 기준으로 순위 계산
  - 조별 진출 등수를 지정해 상위리그 구성
  - 상위리그 진출자를 제외한 참가자로 하위리그 구성
  - 단판 토너먼트와 부전승 자동 배정
  - 라운드별 브래킷 대진표 표시
  - 경기결과 입력 후 다음 라운드 자동 진출
- 모바일 대응 레이아웃
- 일반회원 공개 게임 상세조회
  - 경기요강, 대회현황보기, 신청조회/수정, 경기일정 메뉴
  - 경기종목별 대회정보, 조편성, 참가자, 리그전표, 토너먼트표 조회
  - 경기결과 입력 전에는 참가자 정보, 입력 후에는 조별 순위와 순위별 색상 표시
- 브라우저 `localStorage` 저장

## 실행 방법

```bash
npm start
```

또는

```bash
node server.js
```

브라우저에서 `http://localhost:3000` 을 열면 됩니다.

화면만 확인하려면 `index.html`을 직접 열 수 있으나, 게임 생성과 다른 기기로의 초대는 서버와 DB 연결이 필요합니다.

## 게임 만들기와 초대

- 로그인한 회원은 누구나 게임을 만들 수 있습니다. 장소·일시·게임명·종목·모집인원을 입력하며, 최근 장소와 오늘/내일·인원 버튼을 사용할 수 있습니다.
- 처음에는 ‘새 게임 직접 입력’ 양식을 표시합니다. ‘지난 게임에서 가져오기’는 양식 밖의 접힌 선택 영역에 있으며, 경기를 선택하고 ‘설정 가져오기’를 눌러야 적용됩니다. 불러온 뒤에는 원본 경기명을 표시하고 ‘처음부터 직접 입력하기’로 새 양식으로 돌아갈 수 있습니다.
- 게임명은 날짜·장소로 제안되며 직접 수정할 수 있습니다. 진행방식·정기리그 연결·안내문은 추가 설정에서 지정합니다.
- 서버 저장 성공 후 경기요강에서 생성 완료 안내와 저장된 내용을 먼저 확인합니다. 운영자는 경기요강의 ‘내용 수정’으로 내용을 고치거나 ‘참가자 초대’로 초대 화면을 열 수 있습니다. 이전 참가 명단을 가져온 결과도 생성 완료 안내에 표시합니다.
- 초대 화면에서 경기별 `?game=경기ID` 링크, 공유, QR, 단체방용 문구를 제공합니다. QR은 로컬 JavaScript로 생성하며 외부 QR 서비스에 링크를 전송하지 않습니다.
- 경기요강의 ‘내용 수정’과 ‘참가자 초대’는 아이콘과 테두리를 가진 별도 버튼으로 표시합니다. 기기 공유가 지원되지 않으면 초대 문구를 복사하며, 공유 응답이 8초 이상 없으면 대기 표시를 해제하고 링크 복사를 안내합니다. OS 공유 창 자체를 강제로 닫지는 않습니다.
- QR은 현장에서 다른 사람의 스마트폰 카메라로 읽어 경기요강을 여는 용도입니다. 같은 휴대폰에서 단체방으로 초대할 때는 링크나 초대 문구 복사를 이용합니다.
- 초대 링크로 들어온 비로그인 사용자는 ‘로그인하고 신청’ 또는 ‘비회원으로 신청’을 선택합니다. 로그인 화면을 새로고침해도 원래 경기로 복귀합니다.
- 본인 경기의 ‘같은 설정으로 새 게임’은 설정만 가져오며 날짜를 새로 지정합니다. ‘다음 회차 만들기’는 정기리그 연결도 유지합니다. 참가 명단은 별도 선택 시 기존 일괄등록 API로 등록하며 점수·대진·마감 상태는 복사하지 않습니다.
- 서버 저장 실패 시 입력을 유지하며 공유 가능한 경기를 생성했다고 표시하지 않습니다.

## 회원·비회원 참가신청

- 회원의 이름·성별·부수를 미리 채워 개인전은 ‘이 정보로 참가신청’으로 바로 신청할 수 있습니다. 선수정보는 펼쳐서 수정할 수 있고, 복식·단체전은 팀명을 입력합니다.
- 비회원 신청에는 계정이나 연락처를 요구하지 않습니다. 신청 후 가입은 선택이며 가입하지 않아도 신청은 유지됩니다.
- 비회원 전용 링크는 본인 신청의 조회·수정·취소 권한을 가집니다. 개인적으로 보관해야 하며 단체방 초대 링크와 구분합니다. 브라우저 저장을 지우고 링크도 잃어버렸다면 운영자에게 문의해야 합니다.
- 확인용 비밀값은 암호학적 난수로 만들며 DB에는 해시만 저장합니다. 전용 링크의 비밀값은 URL fragment에서 읽은 뒤 주소창에서 제거하고, API에는 Authorization 헤더로 전달합니다. 공개 경기 응답에 비밀값이나 해시를 포함하지 않습니다.
- 완료 화면에서 회원가입하면 입력한 선수정보를 이어받습니다. 가입과 기존 신청 연결은 같은 DB 트랜잭션으로 처리합니다. 기존 회원도 로그인 후 본인 전용 링크의 확인 정보를 사용해 연결할 수 있습니다. 동일 종목의 회원 신청이 이미 있으면 자동 합치지 않고 충돌을 안내합니다.
- 신청·수정·취소는 서버에서 종목·정원·마감 및 경기 준비 여부를 검사합니다. 회원·비회원 신청은 경기 행 잠금과 트랜잭션으로 정원을 검사하며, 같은 비회원 확인 정보로 재전송해도 신청을 중복 생성하지 않습니다.
- 기존 배포 DB는 새 신청 API의 첫 실행 시 `guest_token_hash` 열과 고유 인덱스를 추가합니다. 신규 구성은 `supabase/schema.sql`에 포함되어 있습니다. 프런트엔드와 서버를 함께 배포해야 합니다.

## 검증 방법

`ttzone` 폴더에서 다음 명령으로 단위·정기리그 회귀 테스트를 실행합니다.

```powershell
node --test tests/*.test.js
```

npm 사용 환경에서는 `npm test`로도 실행할 수 있습니다. 테스트는 실제 클릭 처리와 HTML 생성 코드를 실행하여 추가 API 조회 없는 리그 진입, 비로그인·일반회원·운영자의 연결 경기 열기, 뒤로가기와 다른 리그 이동을 검사합니다. 운영 DB 연결과 실제 브라우저의 화면 배치는 별도 확인이 필요합니다.

Playwright 사용 환경에서는 `node tests/game-invitations.browser.cjs`로 합성 API 데이터를 사용하는 브라우저 통합 검증을 실행합니다. Playwright는 로컬 개발 의존성 또는 `NODE_PATH`로 공급하며, 설치된 Edge를 사용하려면 환경변수 `TTGMS_BROWSER_CHANNEL=msedge`를 지정합니다. 결과 스크린샷 위치는 `TTGMS_UI_OUTPUT`으로 지정할 수 있습니다. 운영 사이트나 실제 DB에 테스트 경기를 생성하지 않습니다.

회원가입 UI는 `node tests/signup.browser.cjs`로 검증합니다. 같은 Playwright 설정을 사용하며, 연락처 공백과 각 필수 항목 누락, 입력값과 오류 표시 유지, 중복 ID·서버·네트워크 오류, 가입 완료 응답 확인과 중복 제출 방지를 합성 API로 검사합니다. 실제 운영 DB의 회원 저장 여부를 확인하는 테스트는 아닙니다.

`node tests/guest-participation.browser.cjs`는 실제 프런트엔드와 실제 API·비밀번호 해시 코드를 로컬 HTTP 서버에서 실행하여 비회원 신청, 전용 링크 복원, 수정·취소, 회원가입 연결, 기존 계정 연결, 회원 간편 신청과 모바일 배치를 검사합니다. SQL 어댑터는 격리된 테스트 대역이며 실제 PostgreSQL 및 운영 DB 검증과는 구분합니다. `tests/participant-registration.test.js`도 실제 API를 실행하되 같은 SQL 대역으로 권한·정원·중복·트랜잭션 동작을 검사합니다.

QR 라이브러리: [qrcode-generator](https://github.com/kazuhikoarase/qrcode-generator) 1.4.4, MIT. 원본 소스와 라이선스는 `public/vendor/`에 포함했습니다.

## 참고

현재 서버에는 회원 인증과 게임·정기리그·참가자 API가 있습니다. 서버에서 `DATABASE_URL`로 PostgreSQL 연결을 설정해야 합니다. 기존 일부 기능의 브라우저 저장 대체 경로와 서버 저장은 구분해서 사용해야 합니다.
